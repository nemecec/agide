## What was built

The work of w-chrome (step 3 of 0035) and w-import (step 5) is one state:

- Theme choice through commands only: the `appearance:set-theme` channel, `AppearanceApi.setTheme`, `ThemeStore.setTheme` and `setThemeId` are removed. The picker changes the theme with `theme_preview` and `theme_apply` and reads the revision and preview from the theme store, so no UI action changes the theme without a command (0035 5.3). `e2e/theme.spec.ts` saves the choice with `theme_apply` and checks that an unknown id is refused and `appearance.json` keeps the earlier choice.
- Aliases against the token set: new `core/theme/vscode/aliasTable.test.ts` checks that every `--vscode-*` alias reads a token of the token set (plain, scheme, mix, scrollbar and shadow values), that each variable is listed once, and the key and token lookups.
- Rail width: the dock holds a group that contains only the profile rail at 52 px (`fixedWidth` in `layout/hostModel.ts`, applied with dockview group constraints in `LayoutHost.tsx`). Before, the rail took a share of the row (about 100 px), and the current bar at the left edge sat far from its tile.
- Removed unused code: `core/theme/themeSetting.ts` and its test (replaced by `themeChoice.ts`), `panes/rail/PlanUsage.tsx`, its tests in `agentsPanes.test.ts` (the `planLine` test stays, the usage meter uses it) and the `.plan-usage` rule in `agents.css`.
- Settings pane: `SettingsPanel.tsx` already hosts the theme picker above the permission and isolation sections, and the title bar gear opens it; no change was needed.
- NOTICE has the Lucide, GitHub Dark Default and Catppuccin Mocha entries; no change was needed.
- `docs/parity.md`: regenerated by `pnpm parity`, unchanged by this step (it lists the theme commands added by w-import).
